## Parent

Part of #2 — [规格：重设计模块 DSL，采用显式实例与出口直连并淘汰旧语法](https://github.com/Naoki326/AnotherFSM/issues/2)

## What to build

让图形编辑器使用者完成“导入新模块脚本 → 创建 Module Instance → 选择公开接口接线 → 导出 → 再导入”的完整工作流。模块接线不再要求设置 terminal 或出口外部别名，保存后仍能恢复相同的流程语义和实例显示属性。

本票包含为这条用户路径必需的图编辑服务、接口数据适配、界面操作、模块感知导出以及演示更新，但不做无关 UI 重构。

**验收边界：本票复用依赖票交付的新 DSL 和核心公开接口规则。** 脚本分析与代码生成的消费者适配由另一张子工单交付，不是本票前置条件。本票只以下述 AC 验收，不把父规格的全部其他要求重复实现一遍。

## Acceptance criteria

- [ ] 通过现有演示／编辑入口可以导入新 DSL，正确显示模块实例、其公开 Input／Output 及外部连接；普通节点和普通事件连接仍保持原有行为。
- [ ] 通过现有界面创建模块实例时，实例内节点和事件按核心规则隔离，默认不再自动建立出口外部别名；实例不是运行时节点。普通节点进入模块、模块出口进入普通节点和模块之间串联均可完成。
- [ ] 接线只使用公开接口；单入口模块可直接选择实例，多入口目标可明确选择公开入口，不能猜测或隐式并行；未知接口、私有内部节点或冲突连接得到明确失败反馈。
- [ ] 接线解析复用核心的实际出口发布者规则；一个出口的多个发布者正确连接，同一接口边不因发布者或分支数量而重复展示或导出，不再依靠 terminal 回退或改写 Branch。
- [ ] 移除或停用模块 terminal 配置、出口外部别名映射及依赖这些机制的界面操作；必要的接口适配与状态展示同步调整，不留下看似可编辑却对新模块无意义的控制项。
- [ ] 实例位置、颜色、显式标识及当前公开接口信息在编辑、导出、再次导入后得到保留；相关 Namespace 和多入口目标身份不丢失。
- [ ] 模块感知导出仅生成父规格定稿的模块声明、实例声明和公开出口接线，保留模块内部基础语法；不输出旧模块 def、terminal 或出口映射配置。
- [ ] 导出使用公开接口元数据规范化实际连接：多发布者的同一出口边去重；目标还原为公开入口或唯一入口实例名；不把私有内部节点名作为新的外部接口泄露。不能用新合同表达的历史映射图明确拒绝导出，不静默改变事件身份。
- [ ] 从现有 Import／Export 公开入口完成往返测试：重新导入后，节点类型、事件与分支绑定、实际转移、公开接口和显式保存的显示元数据等价；覆盖双实例隔离、多入口、多发布者和模块间连接。不要求文本字节相等，也不比较无意义的自动生成内部标识。
- [ ] 在真实界面验证至少一条“导入、创建实例、公开出口接线、导出、再导入”的闭环，并验证旧 terminal／映射配置不再成为操作前提；为本票涉及的服务和接口行为补充自动化验证，不能只依赖手工截图。
- [ ] 更新受本票影响的图形演示默认脚本、模块接口显示和操作说明，使它们可直接运行新 DSL；相关前后端构建和普通节点编辑回归验证通过。
- [ ] 保持 ADR-0002 的前端架构以及核心的编译期展平模型；不引入新的运行时模块调度，不重写画布布局或状态管理，不把平面调试输出改造成模块序列化器，也不做独立 C# Fluent API 全面清理。

阻塞关系使用 GitHub 原生依赖维护；除核心 DSL 票外，本票不依赖脚本分析／代码生成票。
