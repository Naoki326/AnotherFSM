## Problem Statement

当前模块 DSL 把 Module Instance（模块实例）伪装成普通 Node（节点）：用户通过节点声明语法实例化模块，在实例体中把 Output（出口事件）映射成外部 Event（事件），再使用这个外部事件编写 Transition（转移）。额外的 terminal 声明又要求用户理解哪个内部节点负责对外接线。命名映射、出口定位和连线需要分开描述，且数字分支在普通节点和模块实例中具有不同含义，导致语法不直观、难记、难读。

本次改进首先追求语法审美与概念清晰，而不是给旧机制增加另一套等价缩写。另一方面，现有普通转移采用“事件优先”的句型是有意设计：事件是独立概念，不能为了模块简洁，把所有普通节点的事件也改写成节点成员。

用户已明确：可以抛弃原有不合理的模块语法，不要求双语法兼容，也不需要功能相同的第二种模块出口接线方式。

## Solution

保留基础语言的事件优先风格，只为模块的公开接口提供专属接线表达。同一类连接只提供一种规范写法。

### 已定稿的语言表面

| 场景 | 规范写法 | 含义 |
| --- | --- | --- |
| 模块实例声明 | `use Checker as CheckA;` | 将 Module Checker 实例化为 CheckA，不创建同名运行时节点 |
| 普通事件转移 | `Launch -> Start to CheckA;` | 独立事件 Launch 触发从普通节点 Start 进入模块 |
| 模块出口接线 | `CheckA.OK -> NextStep;` | 将 CheckA 公开的出口事件 OK 接向目标节点 |
| 模块之间接线 | `CheckA.OK -> CheckB;` | 将一个模块的出口接向另一个模块的唯一入口 |
| 明确选择入口 | `CheckA.OK -> CheckB.Retry;` | 进入 CheckB 公开的 Retry 入口，而非同时进入所有入口 |
| 普通转移选择模块入口 | `Launch -> Start to CheckA.Retry;` | 保留事件优先句型，明确模块目标入口 |

假设普通节点及 Checker 已定义，主流程可以写成：

```text
use Checker as CheckA;
use Checker as CheckB;

Launch -> Start to CheckA;
CheckA.OK -> CheckB;
CheckA.NG -> ErrorEnd;
CheckB.OK -> NextStep;
CheckB.NG -> ErrorEnd;
StepDone -> NextStep to End;
```

模块仍通过 `module` 定义，通过 `input` 声明公开入口节点，通过 `output` 声明公开出口事件。模块内部的普通节点声明、分支与事件转移沿用基础语法。

- 单入口模块可以直接用实例名作为目标；多入口模块必须明确选择公开入口，不猜测、不隐式并行。
- 同文件中已定义的模块不需要再 import 自身；跨文件模块继续通过现有 import 机制加载。
- 无显示属性时使用分号结束的 use 声明；需要保留位置、颜色或实例标识时，允许 use 声明携带属性块。属性块不是出口映射块。
- 模块出口名称归属于具体实例，不要求用户起外部事件别名，也不产生裸名全局事件。
- 不引入 `::`，不向普通节点推广 `节点.事件 -> 目标`。

### 明确淘汰的旧模块用法

新模块 DSL 不接受以下机制作为兼容入口：借用 def 声明模块实例、terminal 声明、按名称或数字索引配置出口映射，以及使用外部事件加模块实例占位源来替代模块出口接线。普通节点的 def、分支数字索引、事件声明和原有事件优先转移不属于淘汰范围。

这是一项有意的模块 DSL 破坏性变更。旧模块脚本应得到清晰错误并按新语法迁移，而不是被静默跳过、猜测转换或当作普通节点执行。

## User Stories

1. 作为脚本作者，我希望模块实例有独立的声明方式，以便一眼区分模块复用与普通节点创建。
2. 作为脚本作者，我希望没有额外配置的模块实例只需一行声明，以便简单流程不必书写空配置块。
3. 作为脚本作者，我希望直接通过实例的公开出口接线，以便不用先创造一个外部事件别名。
4. 作为脚本作者，我希望模块出口只有一种规范接线方式，以便不用在等价写法间选择。
5. 作为脚本作者，我希望普通事件转移继续采用原有句型，以便保留事件独立于节点的含义。
6. 作为脚本作者，我希望普通节点不能套用模块出口短写法，以便语法简化不改变基础事件模型。
7. 作为模块作者，我希望继续通过 Input 和 Output 描述接口，以便调用者无需阅读模块实现。
8. 作为模块作者，我希望不再声明 terminal，以便不重复维护出口事件与发布节点之间的关联。
9. 作为模块作者，我希望保留模块内部普通节点的分支与转移写法，以便复用已有的基础语言知识。
10. 作为模块使用者，我希望唯一入口可以省略入口名，以便常见场景保持简洁。
11. 作为模块使用者，我希望多入口时可以明确选择公开入口，以便决定本次从哪个节点开始执行。
12. 作为模块使用者，我希望省略多入口选择时得到明确错误，以便不会意外执行多个入口或遭遇间接的重复转移错误。
13. 作为模块使用者，我希望一个模块出口可以直接连接另一个模块，以便清楚表达流程组合。
14. 作为模块使用者，我希望模块出口可以连接普通节点，以便模块与现有流程自然衔接。
15. 作为模块使用者，我希望普通节点的事件转移可以进入模块，以便无需修改原有普通节点的事件定义。
16. 作为模块使用者，我希望一个 Module 可以多次实例化，以便复用流程定义而不共享实例内的节点或事件。
17. 作为模块使用者，我希望不同实例的同名 Output 保持独立，以便连接一个实例不会影响另一个实例。
18. 作为脚本作者，我希望同名普通事件与模块出口不会自动合并，以便模块接口归属不会改变全局或 Namespace 内普通事件的身份。
19. 作为模块作者，我希望出口可以由入口节点、中间节点或末端节点发布，以便提前失败等结果不需要人为增加终止节点。
20. 作为模块作者，我希望同一出口由多个内部节点发布时都能正确接向外部目标，以便调用者无需知道具体发布者。
21. 作为模块作者，我希望多个分支发布同一出口时不会生成重复转移，以便接口接线反映真实行为而非分支数量。
22. 作为模块使用者，我希望未公开的内部事件不能冒充模块出口，以便 Module 的公开接口有明确约束。
23. 作为模块使用者，我希望外部进入模块时只能选择公开 Input，以便内部节点重构不会被隐藏的外部接线绑死。
24. 作为脚本作者，我希望未知模块、实例、出口或入口都有可定位的错误，以便快速修正拼写或接口使用问题。
25. 作为脚本作者，我希望冲突的目标转移明确失败，以便编译器不会覆盖已有连接或擅自修改 Branch。
26. 作为脚本作者，我希望新模块引用可以与 Namespace 共存，以便不需要为模块再学习另一套命名空间符号。
27. 作为脚本作者，我希望点号名称按声明的实际身份解析，以便普通带限定名的事件不会被误判为模块出口。
28. 作为模块使用者，我希望同文件定义的模块可以直接使用，以便不必重复导入已在当前脚本中的定义。
29. 作为模块使用者，我希望跨文件导入继续工作，以便模块仍然可以拆分和复用。
30. 作为图形编辑器使用者，我希望实例的位置、颜色和标识仍能保存，以便语法简化不丢失画布信息。
31. 作为图形编辑器使用者，我希望模块接线不再依赖 terminal 或出口别名设置，以便界面与新 DSL 表达同一个模型。
32. 作为脚本导出使用者，我希望导出只产生新模块写法，以便不用手工清理已淘汰语法。
33. 作为脚本导出使用者，我希望导出后重新导入保留相同的流程结构和公开接口，以便脚本可以可靠保存与共享。
34. 作为代码生成使用者，我希望包含新模块语法的脚本仍能正常构建和初始化，以便现有脚本集成入口不会失效。
35. 作为已有普通脚本的使用者，我希望不含旧模块机制的脚本保持原有行为，以便模块语法升级不会迫使所有流程重写。
36. 作为旧模块脚本的维护者，我希望过时写法被明确拒绝并得到迁移方向，以便不会得到看似成功但实际缺少模块或转移的流程。
37. 作为项目维护者，我希望编译结果仍是普通节点、事件和转移，以便无需改变 FSMExecutor 的执行模型。
38. 作为项目维护者，我希望文档、示例、导出与错误提示使用同一套模块语法，以便用户不会再次遇到多个相互矛盾的入口。

## Implementation Decisions

1. **范围是模块 DSL 的替换，不是基础转移语言重写。** 保留普通节点、普通 Branch、独立 Event 和事件优先 Transition 的含义。模块出口短写法必须先解析到真实的 Module Instance 及其公开 Output，不能仅凭字符串包含点号启用。
2. **实例声明与节点声明分离。** 修改语法解析和脚本构建，使 use 成为模块实例的唯一 DSL 声明入口；def 不再通过模块注册表偷偷切换成模块展开。若旧声明指向的只是模块而非合法节点类型，应报告需要迁移，不能创建伪节点。同名的真实节点类型仍按普通节点规则处理。
3. **模块接口继续使用 Input 和 Output。** Input 指真实的内部节点，Output 指真实的出口事件，不引入出口节点概念。模块定义的公开入口必须能解析到模板节点；被用于接线的出口必须有实际发布节点。未接线的有效出口允许存在，不强迫调用者消费所有结果。
4. **取消脚本级 Event Mapping。** 新实例不接受名称映射、数字索引映射或外部事件别名配置。实例内出口事件使用实例限定的身份，不自动创建同名裸事件，也不把不同实例的出口合并。调整输出声明顺序不能改变任何按名称书写的接线含义。
5. **取消 terminal 机制在新 DSL 中的职责。** 不解析 terminal 声明，不通过 terminal 猜测来源，也不为使连接成功而改绑节点 Branch。出口来源由模板中真实发布该 Output 的节点确定，允许非末端节点和多个发布者。
6. **保持编译期展平。** 模块模板和实例不是运行时执行节点；展开后的节点和事件仍以实例限定名进入父 FSMEngine。普通转移、分支和执行器继续处理原有运行时对象，不新增子引擎、桥接执行器或模块专属调度机制。发布 Output 不表示停止整个执行器。
7. **入口解析明确且统一。** 裸实例目标只在其恰有一个公开 Input 时成立；多个入口必须选择具体公开入口；零入口目标应明确失败。普通转移进入模块、模块出口进入模块共用相同规则，不为多入口生成隐式并行转移。
8. **限制跨模块接线到公开接口。** 新模块出口引用不能访问未声明的内部事件；外部模块目标不能绕过 Input 直接进入私有内部节点。模块内部的普通节点和事件引用不受影响。这里不新增运行时访问控制或隐藏引擎的公开调试查询能力。
9. **保留转移的唯一目标约束。** 一个真实源节点与同一事件只能有一个目标。多个发布节点各自连接到同一外部目标是合法展开；同一节点的多个同事件分支要去重。与既有内部转移或其他外部连接冲突时报告错误，不覆盖、不改事件、不悄悄选择某个目标。
10. **Namespace 与模块接口是不同概念。** 新实例声明和出口引用应在现有 Namespace 范围内工作，也应支持对真实限定实例名的引用。模块接口解析必须结合注册实例和公开接口元数据，保留普通事件名称的原有解释；不能增加新的命名空间分隔符，也不能将所有点号表达式视为成员访问。出现真实名称冲突或多种有效解释时应诊断，不能自动合并对象。
11. **维持现有导入职责。** 同文件的已定义模块直接可用；外部模块继续走注册或 import 加载入口及现有相对路径规则。未知模块和循环引用仍应失败。本规格不新增嵌套模块实例化、任意前向引用或新的包查找系统。
12. **实例属性块仅保存既有元数据。** 无属性使用简洁声明；有属性时允许保存 Pos、Color 和 FlowID。属性块不能接受普通节点 Branch、出口映射或新的运行时配置含义。
13. **复用现有编译与解析模块。** 修改脚本语法、状态与转移构建、模块模板和实例元数据所组成的现有编译链。公开接口解析与出口发布者定位应有一个权威实现，供脚本构建和必要的图编辑适配调用，避免继续保留互相矛盾的 terminal 与映射回退分支。不新增只为测试服务的公开接口。
14. **拒绝旧模块语法是可观察契约。** 语法错误或接口错误必须传播为脚本构建失败；不能仅输出解析器错误后继续生成貌似有效的流程。已有 Try 类入口应相应返回失败。错误信息至少指出涉及的模块、实例、接口名或旧语法类别；已淘汰模块写法应给出迁移方向。
15. **原有普通转移不成为模块出口的第二入口。** 以模块实例占位源、再指定外部事件的旧出口接线方式不予支持；普通节点作为来源的事件优先转移仍有效，包括目标为模块的情形。普通节点的分支数字索引不因淘汰模块数字出口映射而被删除。
16. **已有脚本消费入口跟随新语法。** 文件加载、已有的转移重建入口和脚本分析消费者不能静默遗漏 use 声明或模块出口连接；转移重建沿用既有生命周期契约，不借此重写执行模型。代码生成消费者应能构建并初始化新模块脚本，且不能把模块视觉代理当成可查询的运行时节点；不要求新增模块专属强类型代码生成接口。
17. **模块感知导出使用唯一规范形式。** 导出应保留模板接口、实例名称、相关元数据和连接，并输出新实例声明及模块出口连接；不输出 terminal、映射配置或旧模块 def。多个发布者对应同一条接口连接时应规范化去重，目标应还原为公开入口或唯一入口实例名。平面调试输出与模块感知导出不是同一个合同，不要求把所有字符串表示都升级为模块序列化器。
18. **更新必要的现有消费者，不重做编辑器。** 迁移仓库内模块示例、演示脚本和文档；导入、创建模块实例、接线及导出的既有演示路径应采用新接口语义，不能继续要求设置 terminal 或外部出口别名。可以移除或停用对应的旧界面操作，并调整必要的数据适配；不进行无关的布局、状态管理或前端架构重构。
19. **破坏性变更限定在上述模块语法与依赖路径。** 不要求旧模块 DSL 继续可执行，不提供兼容模式或自动迁移器。也不因本规格而笼统删除所有 C# Fluent API、公共模型字段或无关的普通脚本功能；内部实现可按依赖清理，独立的程序化 API 重设计不属于验收目标。导出遇到不能用新模块合同表示的历史映射图时应明确拒绝，不能静默改变事件身份。
20. **显式修订 ADR-0001 的相关决策。** 保留编译期展平、Input/Output、循环依赖检测、视觉代理和文件发现原则；替换原有复用 def 实例化、强制事件映射及模块实例源占位接线的约定。文档应解释此次调整源于语法审美、公开接口归属和单一写法原则；Event Mapping 术语不得继续被描述为新 DSL 的必需步骤。保持 ADR-0002 的前端架构决策不变。

## Testing Decisions

### 测试 seam

- 主要 seam 使用现有 FSMEngine 的公开脚本入口，以完整 DSL 文本经 CreateStateMachine 构建流程；需要跨文件时使用现有注册或文件加载入口。通过 GetNode、GetEvent、节点的公开转移查询和实例元数据验证结果。
- 不直接断言 ANTLR 产生的语法树形状、Visitor 调用次数、私有字典实现或某个内部辅助函数；不 mock 编译器或转移解析。使用实现真实 Branch 与 Transition 行为的轻量节点工厂，避免依赖设备或外部服务。
- 模块感知导出额外使用现有 EngineManager 的 Import／Export seam 做往返测试。重新导入后比较可观察流程语义，而不是要求导出文本字节级相同。
- 必要的脚本消费适配通过已有公开分析或生成入口做少量合同测试和构建烟测；核心模块语义不在每层重复测试。无需为本功能新增公开 seam。

### 必须覆盖的行为

1. 新实例声明、无属性和带既有显示属性的形式可以构建；模块实例不出现在运行时节点集合中。
2. 普通节点进入单入口模块、模块出口进入普通节点、模块之间串联，均连接到正确的真实节点。
3. 多入口显式选择正确；裸多入口目标、零入口目标、未知或非公开入口明确失败，不产生隐式并行。
4. 出口由入口或中间节点发布时仍正确接线；同一出口多个发布者全部接线；同一节点多个同出口分支不会重复生成转移。
5. 两个实例的节点、内部事件和出口事件均隔离；公开出口与同名普通事件不混淆；出口声明重排不改变绑定。
6. 未公开内部事件、未知实例或出口、已接线但没有真实发布者的出口、普通节点冒充模块出口等情况均失败。
7. 同一源节点和事件指向不同目标、接口连接与内部连接冲突、实例或限定名碰撞等情况明确失败，不覆盖既有语义、不改写 Branch。
8. Namespace 中的实例与出口正常解析；合法的既有带点号事件和节点名仍按普通转移规则解释，不因新短语法被重分类。
9. 不含模块的普通节点定义、事件定义、数字及命名分支结果、事件优先转移行为保持不变；普通节点指向模块入口的转移同样保留事件身份。
10. 旧模块 def、terminal、名称映射、数字映射和旧外部事件加模块占位源接线均不能作为新模块兼容入口；失败必须可从公开构建或 Try 类入口观察，不能只写解析日志。
11. 同文件定义不要求重复 import；注册模块与文件导入均可使用新实例语法；未知模块、缺失文件和循环引用保留清晰错误。
12. 模块感知导出只生成新模块形式；多发布者的接口边不重复；多入口目标不丢失选择；重新导入后节点类型、分支事件、转移、接口和显式保存的显示元数据等价。内部自动生成标识及无意义的文本顺序不作为等价条件。
13. 现有转移重建入口能理解新模块出口连接；相关脚本分析和代码生成示例能构建、初始化，不输出指向不存在模块运行时节点的假引用。
14. 现有演示的导入、模块实例创建、公开出口连接和导出路径不再生成旧映射或 terminal 依赖；为迁移所必需的显示适配不改变普通节点接线行为。

### 现有测试先例

- FSMEngineFacts 与 EngineWiringFacts 通过公开入口和真实结果验证引擎行为，可沿用相同测试风格。
- 当前工作区的 ModuleScriptFacts 已展示入口解析、真实出口发布者、双实例隔离与非法映射诊断等案例；其中保留基础不变量的案例应迁移到新 DSL，而不是把旧语法固化为兼容性要求。
- ScriptNodeFactory 提供真实节点分支与转移行为，可作为轻量测试适配器参考。现有脚本分析测试程序包含模块注册、构建和执行场景，可用于适配烟测，但不能只依靠控制台输出作为断言。
- 本次主要变化位于编译期，不需要为每个语法案例启动 FSMExecutor；是否复用已有执行烟测以确认路由，应以公开行为验证需要为准。

## Out of Scope

- 将普通事件优先连线改成普通节点成员访问风格，或重新设计所有基础节点与分支语法。
- 同时保留两种等价的模块出口接线方式、增加出口别名或数字映射的新变体。
- 旧模块 DSL 的兼容模式、弃用过渡开关、自动迁移工具，以及任意历史模块图的无损自动转换。
- 新的运行时模块隔离、独立子引擎、执行器桥接、参数传递、返回值系统或并行执行模型。
- 新增嵌套模块实例化、嵌套 Namespace 能力、通用包管理或普遍的定义顺序无关解析。
- 对独立 C# Fluent API 的全面重设计、所有历史公开字段的清理，或增加新的强类型模块代码生成 API。
- 无关的前端重构、绘图布局优化、UI 换代，以及把平面调试输出改造成模块序列化格式。
- 对所有脚本失败实施完整事务回滚、全面诊断基础设施重写或其他与本语法交付无关的重构。

## Further Notes

- 这份规格来自本次会话已经定稿的设计，而非新增访谈。关键约束是：基础转移保持事件优先；模块出口具有实例归属；模块专属短写法不推广到普通节点；同一用途不提供第二套等价语法。
- 用户最新补充明确允许抛弃旧模块语法。因此旧模块机制不构成向后兼容验收条件，保留它们反而会违背这次收敛目标；需要保护的是普通脚本语义和编译期展平架构。
- 采用前一轮提出的“公开脚本构建为主、模块感知导入导出往返为辅”的测试边界；最新补充在此基础上加入旧模块语法拒绝测试。
- 这是对 ADR-0001 表层语言决策的有意调整，不是取消该 ADR 的运行时架构选择。实现时必须同步解释该差异，而非默默让文档与代码继续分叉。
- 当前工作区的 ModuleScriptFacts 与 ScriptNodeFactory 是未跟踪文件。本规格发布不会改写它们，不能把它们当作已经提交或已经通过 CI 的基线；后续实现前应保留并确认当时工作区状态。
- 本工单记录规格，不代表功能已实现或测试已通过。若后续需要拆成实现票，应按独立验收目标划分并建立依赖；每个实现会话只处理一个 ticket，本次不开始认领或实现。
